# US-002 - Gantt Charts

## 📌 Описание

**Как** менеджер проектов, **я хочу** видеть диаграммы Гантта для своих проектов, **чтобы** эффективно планировать и отслеживать выполнение задач, визуально оценивать зависимости между задачами и сроки выполнения проектов.

---

## 🎯 Контекст

### Персона
- **Имя:** Иван, менеджер проектов
- **Описание:** Управляет несколькими проектами одновременно, работает с командой
- **Цель:** Эффективно планировать проекты, отслеживать прогресс, управлять зависимостями

### Текущая проблема
В текущей версии Floktask задачи отображаются в виде списков, Kanban доски и календаря. Отсутствует специализированный инструмент для управления проектами с множеством взаимосвязанных задач. Это затрудняет:
- Визуализацию общего плана проекта
- Отслеживание зависимостей между задачами
- Оценку критического пути проекта
- Планирование ресурсов и времени

### Аналоги у конкурентов
- **Microsoft Project:** Полноценные диаграммы Гантта
- **ClickUp:** Gantt View с зависимостями
- **Asana:** Timeline View (похож на Гантт)
- **Jira:** Gantt Charts через плагины
- **Notion:** Gantt через базы данных

## ✅ Критерии приемки (Acceptance Criteria)

### Функциональные требования

- [ ] **Отображение диаграммы Гантта**
  - Горизонтальная временная шкала
  - Задачи отображаются как горизонтальные полосы
  - Длина полосы соответствует длительности задачи
  - Положение на шкале соответствует датам начала/окончания
  
- [ ] **Поддержка зависимостей**
  - Отображение стрелок между зависимыми задачами
  - Автоматическое пересчитывание дат при изменении зависимостей
  - Обнаружение циклических зависимостей
  
- [ ] **Критический путь**
  - Визуальное выделение критического пути
  - Автоматический расчет критического пути
  - Предупреждение при изменении критического пути
  
- [ ] **Управление задачами**
  - Drag-and-drop для изменения дат
  - Drag от краев для изменения длительности
  - Создание зависимостей перетаскиванием
  
- [ ] **Группировка и фильтрация**
  - Группировка по проектам, этапам, ответственным
  - Фильтрация по статусу, приоритету, тегам
  - Поиск по задачам
  
- [ ] **Отображение прогресса**
  - Процент выполнения для каждой задачи
  - Визуальная индикация прогресса на диаграмме
  - Отображение общего прогресса проекта
  
- [ ] **Милистоны и этапы**
  - Поддержка милистоунов
  - Визуальное разделение на этапы
  - Автоматическое создание этапов
  
- [ ] **Ресурсы**
  - Отображение ответственных за задачи
  - Распределение нагрузки по ресурсам
  - Обнаружение перегрузки ресурсов

### Нефункциональные требования

- [ ] **Производительность**
  - Отображение до 500 задач без задержек
  - Плавный скролл и зум
  - Быстрое пересчитывание зависимостей
  
- [ ] **Адаптивность**
  - Работа на десктопах (приоритет)
  - Работа на планшетах
  - Адаптированный интерфейс для мобильных
  
- [ ] **Печать и экспорт**
  - Экспорт в PDF
  - Экспорт в PNG/SVG
  - Печать диаграммы

### Дизайн требования

- [ ] **Визуальный стиль**
  - Соответствие текущему дизайн-системе
  - Четкие визуальные индикаторы зависимостей
  - Цветовое кодирование по статусу/приоритету
  
- [ ] **Взаимодействие**
  - Интуитивный drag-and-drop
  - Четкое визуальное выделение при выборе
  - Контекстные подсказки

   - Клик по задаче открывает карточку с деталями

   - Автоматическое пересчитывание дат

5. **Просмотр деталей:**
   - Клик по задаче для просмотра деталей
   - Контекстное меню для быстрых действий

## 📋 User Journey

### Сценарий 1: Планирование проекта
1. Пользователь открывает Gantt Chart для проекта
2. Видит все задачи проекта на диаграмме
3. Перетаскивает задачи для установки дат
4. Создает зависимости между задачами
5. Видит автоматически рассчитанный критический путь
6. Экспортирует диаграмму для отчета

### Сценарий 2: Отслеживание прогресса
1. Пользователь открывает Gantt Chart
2. Видит прогресс выполнения каждой задачи
3. Визуально оценивает, какие задачи отстают
4. Корректирует план для уложиться в сроки
5. Перераспределяет ресурсы

### Сценарий 3: Обнаружение проблем
1. Пользователь добавляет новую задачу
2. Система автоматически пересчитывает зависимости
3. Обнаруживает конфликт в критическом пути
4. Предупреждает пользователя
5. Предлагает варианты решения

## 💡 Технические примечания

### Архитектура
- **Клиент:** Compose (Android), SwiftUI (iOS), React (Web)
- **Сервер:** API для расчета зависимостей и критического пути
- **База данных:** Хранение зависимостей между задачами
- **Алгоритмы:** Расчет критического пути, обнаружение циклов

### Производительность
- **Максимальное количество задач:** 500
- **Время рендеринга:** < 1s
- **Время пересчета зависимостей:** < 100ms
- **FPS при зум/скролле:** > 40

### Алгоритмы

**Расчет критического пути:**
```
1. Построение графа зависимостей
2. Вычисление раннего начала (ES) и раннего окончания (EF)
3. Вычисление позднего начала (LS) и позднего окончания (LF)
4. Определение критического пути (где ES = LS)
5. Визуальное выделение критического пути
```

**Обнаружение циклов:**
```
1. Построение графа зависимостей
2. Проверка на наличие циклов (DFS или Topological Sort)
3. Визуальная индикация циклических зависимостей
4. Предложение вариантов разрешения
```

**Автоматическое перепланирование:**
```
1. Изменение даты задачи
2. Обновление зависимых задач
3. Пересчет критического пути
4. Обнаружение конфликтов
5. Предложение вариантов разрешения
```
