## 📋 Исполнительное резюме

Функция коллаборации в Floktask позволит пользователям работать вместе над проектами, делиться задачами и координировать свою работу. Это критически важно для:
- **Командной работы** над проектами
- **Семейного использования** (общие списки покупок, планы)
- **Совместной работы** с клиентами и партнерами
- **Управления проектами** в организации

Цель: сделать Floktask удобным инструментом для совместной работы, сохраняя при этом простоту использования для индивидуальных пользователей.

## 🎨 User Journey

### Сценарий 1: Создание общего проекта
1. Пользователь создает проект
2. Кликает "Поделиться" или "Добавить участников"
3. Выбирает способ приглашения (email или ссылка)
4. Указывает уровень доступа для каждого участника
5. Участники получают уведомление и присоединяются к проекту
6. Все участники видят задачи проекта

### Сценарий 2: Работа с общей задачей
1. Участник открывает общую задачу
2. Видит комментарии других участников
3. Добавляет свой комментарий
4. Упоминает другого участника (@user)
5. Отмечает задачу как выполненную
6. Все участники получают уведомление об изменениях

### Сценарий 3: Управление проектом
1. Владелец проекта открывает настройки
2. Видит список участников
3. Изменяет роли участников
4. Добавляет новых участников
5. Удаляет участников
6. Настраивает уведомления для проекта

## 🏗️ Техническая архитектура

### Модель данных

```kotlin
// Участник проекта
data class ProjectMember(
    val id: Long,
    val projectId: Long,
    val userId: Long,
    val role: ProjectRole,
    val joinedAt: Instant,
    val invitedBy: Long? = null
)

enum class ProjectRole {
    OWNER,       // Владелец проекта (полный доступ)
    ADMIN,       // Администратор (управление участниками)
    EDITOR,      // Редактор (редактирование задач)
    VIEWER       // Наблюдатель (только чтение)
}

// Комментарий
data class Comment(
    val id: Long,
    val taskId: Long,
    val userId: Long,
    val content: String,
    val createdAt: Instant,
    val updatedAt: Instant? = null,
    val mentions: List<Long> = emptyList(),  // IDs упомянутых пользователей
    val reactions: Map<String, Int> = emptyMap()  // Emoji → count
)

// История изменений
data class ChangeHistory(
    val id: Long,
    val taskId: Long,
    val userId: Long,
    val changeType: ChangeType,
    val oldValue: String? = null,
    val newValue: String? = null,
    val timestamp: Instant,
    val field: String  // Какое поле изменилось
)

enum class ChangeType {
    CREATE, UPDATE, DELETE, COMPLETE, ARCHIVE
}

// Уведомление
data class CollaborationNotification(
    val id: Long,
    val userId: Long,  // Кому отправлено
    val type: NotificationType,
    val entityId: Long,  // ID задачи/проекта/комментария
    val entityType: EntityType,
    val fromUserId: Long,  // Кто выполнил действие
    val message: String,
    val isRead: Boolean = false,
    val createdAt: Instant
)

enum class NotificationType {
    TASK_CREATED, TASK_UPDATED, TASK_DELETED, TASK_COMPLETED,
    COMMENT_ADDED, COMMENT_MENTIONED, PROJECT_INVITED
}

enum class EntityType {
    TASK, PROJECT, COMMENT
}
```

### Алгоритмы

**Разрешение доступа:**
```
функция имеетДоступ(userId, projectId, action):
    member = получитьУчастника(userId, projectId)
    если member == null: вернуть false
    
    возвращать когда:
        member.role == OWNER -> true
        member.role == ADMIN -> action не в [DELETE_PROJECT, MANAGE_MEMBERS]
        member.role == EDITOR -> action в [READ, CREATE_TASK, UPDATE_TASK, DELETE_TASK]
        member.role == VIEWER -> action == READ
        иначе -> false
```

**Упоминания:**
```
функция обработатьКомментарий(content, taskId, userId):
    mentions = найтиУпоминания(content)  // @user
    для каждого user в mentions:
        создатьУведомление(
            userId: user,
            type: COMMENT_MENTIONED,
            entityId: taskId,
            entityType: TASK,
            fromUserId: userId,
            message: "Вас упомянули в комментарии к задаче"
        )
    сохранитьКомментарий(content, taskId, userId)
```
